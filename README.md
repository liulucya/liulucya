我常觉得，方言语音研究里最难的往往不是模型，而是“数据到底算不算对”。同一个“上海话”的词，老派和新派读法可以差很远；转写者听三遍也可能还是会漏掉喉塞音。下面这些内容是我现在的工作片段，写下来既是为了整理，也方便合作者知道我在哪里、卡在哪里。

## 我习惯怎么合作

先说结论：我希望讨论从“我不确定什么”开始。方言语音没有那么多标准答案，每个口音背后都有具体的人、地方和语言变化。承认不确定，后面的实验才不会被一个看似统一的标注骗住。

- 每次发数据前，先把样本按“能听清 / 听不清 / 转写存疑”分成三堆。这样对方不用替我猜，也能直接指出错误最密的那一堆。
- 失败的实验照样写成笔记。一个错误词表或者一组奇怪的 attention 权重，往往比一次漂亮的 benchmark 更能说明问题。
- 拿不准发音时，我默认去找人问，而不是自己造一个“标准音”。之前有份苏州话的语料把“白”读成入声的地方漏标了，后来发现是切分边界错了，不是声学特征的问题。

在协作上，我最喜欢收到具体的、带文件名的反馈，比如“第 47 句的第 2 秒，声母听起来像清音”。这样的反馈可以直接变成修正规则，而不是停留在印象层面。

## 正在做的两个原型

### 1. 吴语口语转写校对工具

**问题**：公开的吴语语料里，很多转写会把入声韵尾、浊塞音和连续变调“抹平”成普通话的常见读法。模型在这些数据上训练，学的不是真正的吴语，只是普通话发音加了一点吴语词汇。

**做法**：我试着做了一个基于强制对齐的校对界面。先用 Montreal Forced Aligner 把音频按句切开，再让人逐句听写，同时把原始转写放在旁边对比。界面刻意不自动给出“标准答案”，因为一旦出现一个默认选项，标注者会下意识地去选，而不是听。

**取舍**：自动纠错看起来很省事，但错的方向很难预测。比如某个模型会把“五”听成普通话的“wu”，在苏州话里这个字其实是“ng”。如果我让模型自动“修正”，它反而会把正确的方言读音改掉。所以现在的做法是：让标注者快速标记“这里听不清”“这里声母存疑”，具体修不修，留给后续的语音学核对。

**目前走到哪**：上海话试点从最初 5 位朋友扩到了 15 位左右，每个人的口音背景都做了记录。发现最有用的不是界面功能，而是给每个标注者发一份“常见问题听辨表”，里面有清浊对立的最小对立对，比如“爸”和“怕”在上海话里的声母差异。

**下一步**：再收 5 位不同年龄段的发音人，把标注规范从“上海话”细化到“新派/中派/老派”三档，先把标注者之间的分歧率跑出来。

### 2. 南方方言“可懂度”测试集

**问题**：经常有人问“这个模型能听懂江苏、浙江、福建的方言吗？”但这个问题太大了。我想做的是一个小规模测试集，只回答一个具体问题：模型听同一句话在苏州、温州、福州的口语说法时，能听懂多少。

**做法**：找朋友用各自最自然的方式把一组场景句子说出来，不做朗读腔。句子不长，但特意选了容易在口语里变调、弱读、吞音的表达。目前只有 50 题，不求数量多，只求每题都能稳定暴露模型的某个错误模式。

**取舍**：一开始想把各地口音都覆盖到，结果发现每多一个点，标注工作量就翻一倍。后来决定先做“上海—苏州—温州”这三条线路，因为它们在声母、韵母和连续变调上的差异足够大，能最快看出模型的“泛化”是真是假。

**下一步**：公开之前，先找几个非技术朋友做一遍听感检查，确保题目用方言读出来是自然的，而不是照着汉字念。再跑一组 baseline，按方言点分开记成绩，而不是混在一个平均值里。

## 为什么走到这条路上

我小时候在外婆家听苏州话，总觉得大人说话像唱歌，高低起伏的调子比普通话好玩得多。后来在语音学课上第一次学到“连续变调”和“发声态”，才明白那种“唱歌感”背后是有规则的，不是随便哼出来的。

读研之后开始做语音模型，慢慢发现最缺的不是网络结构，而是能被模型听见的、标注靠谱的方言数据。很多公开语料规模不小，但转写质量经不起细看。于是我从 2023 年开始把一半时间花在“数据考古”上：翻旧录音、对比不同版本的转写、问朋友某个字在她们家乡到底怎么读。

这条路没有标准路线图。我现在的日常就是记笔记、写小脚本、做标注实验，偶尔跑一跑模型看看自己的直觉对不对。每次发现一个被转写“抹平”的方言特征，都会觉得这件事值得继续做。
